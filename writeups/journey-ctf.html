1. Artefato inicial

O arquivo tem 74.933.929 bytes, mas é um fonte Go legítimo. O conteúdo principal é uma constante hex gigante (gogogo, ~75 MB de hex = 37,4 MB de bytes) mais um decodificador:

  • s0() decodifica hex e aplica XOR 0xAA — usado para nomes e mensagens.
  • deByte() decodifica cada byte do blob com uma máscara dependente do índice.
  • Os 4 primeiros bytes decodificados são o tamanho (big-endian) do payload seguinte.
func deByte(i int, y byte, binbash byte) byte {
    b := byte((uint32(i)*uint32(i) + 31*uint32(i) + uint32(binbash)) & 0xFF)
    t := byte((uint16(y) - uint16(b)) & 0xFF)
    u := byte((uint16(t) * 13) & 0xFF)
    return (u >> 1) | (u << 7)   // rotate right 1
}

Reimplementando em Python:

pt = bytes(debyte(i, c) for i, c in enumerate(ct))
n  = int.from_bytes(pt[:4], "big")
payload = pt[4:4 + n]

Saída: standard.journey (fonte C) e a mensagem "This Google language is a bit unusual, maybe I should go back to the standard".

3. Camada C — standard.journey

O fonte C contém 72 arrays L0..L71 com os bytes cifrados, os tamanhos reais em Q_LENS e um salt por linha em Q_SALT. O decoder:

st = 0xC0FFEE00 ^ (li * 0x9E3779B9) ^ n ^ (salt << 24)
st ^= (st << 13); st ^= (st >> 7)

for j in range(n):
    t = ror3((data[j] - salt) & 0xFF)
    k = (xs32(st) ^ (li * 131) ^ j) & 0xFF
    out[j] = ((t ^ k) - ((j + li) & 0xFF)) & 0xFF

O array L6 tem ~6 MB — é o payload real; os outros são linhas pequenas de código. Saída: snake.journey (Python) e a mensagem "C is only one letter; less is faster, but I also want to fight snakes...".

Decoys: opq() usa (x & 0xF) == 0x11, que é impossível (0x11 = 17 > 15). O mesmo padrão aparece em todas as camadas.

4. Camada Python — snake.journey

Blob zlib + XOR com keystream derivado de SHA-256(salt + r + salt), repetido 10 vezes:

for r in reversed(range(10)):
    y = zlib.decompress(y)
    y = xor(y, hashlib.sha256(salt + bytes([r]) + salt).digest())

Saída: rusted.journey (Rust), com a mensagem "Python is pretty slow, I am afraid my computer has rusted by now".

5. Camada Rust — rusted.journey

O blob hex é concatenado e decodificado com a chave 1337coffee:

let key = b"1337coffee";
decoded[i] = ror1(blob[i] ^ ((i * 131) & 0xFF) ^ key[i % key.len()]);

Saída: haskell.journey. Mensagem: "Now that I am all rusted up, I should use a classic again".

6. Camada Haskell — haskell.journey

Depois de concatenar os 32 blocos hex, cada byte recebe uma subtração posicional (índice 1-based):

k3[i] = (k1[i] - (i + 1)) % 256

Saída: coffee.journey (Java). Mensagem: "Haskell was exhausting, now I need some coffee first!".

7. Camada Java — coffee.journey

A camada mais “profissional”. O programa:

  • Usa reflection para pegar todos os campos cappuccino_NNN (3 dígitos), ordena e concatena os valores base64.
  • Deriva a chave com PBKDF2WithHmacSHA256: senha espresso-beans-42, salt de 16 bytes, 9541 iterações e chave de 256 bits.
  • Decifra com AES/GCM/NoPadding, IV de 16 bytes e AAD igual ao nome do arquivo (awake.journey).
PBEKeySpec("espresso-beans-42".toCharArray(), salt16, 9541, 256)
Cipher.getInstance("AES/GCM/NoPadding")
c.updateAAD("awake.journey".getBytes(UTF_8))

Saída: awake.journey (Brainfuck). Mensagem: "After so much coffee I feel wide awake; my brain is completely scrambled".

8. Camada Brainfuck — awake.journey

O programa só usa +, - e . — sem loops nem ponteiros. É uma sequência linear que imprime 28.740 bytes:

cell = 0
for ch in code:
    if ch == '+': cell = (cell + 1) & 0xFF
    if ch == '-': cell = (cell - 1) & 0xFF
    if ch == '.': out.append(cell)

A saída é uma mensagem ("Now I would like to mine rubies. But how?") seguida de um blob base64 que decodifica para ruby.journey.

9. Camada Ruby — ruby.journey

O payload tem um header próprio: JRNYv2\0\0 + número de rodadas (6) + tamanho da chave (24) + salt (24 bytes) + flag de gzip + tamanho esperado. O decode é um XOR com keystream SHA-256(salt + rodada):

for h in range(doha - 1, -1, -1):
    manila = sha256(cairo + struct.pack(">I", h)).digest()[:naples]
    vienna = xor(vienna, manila)

if lima_f & 1:
    vienna = gzip.decompress(vienna)

Saída: healthy_food.journey (Emojicode). Mensagem: "I found a ruby in the mine! But now I am really hungry for some grapes!".

10. Camada final — Emojicode

O programa declara 8 constantes (mango=90, guava=17, papaya=204, lychee=51, durian=113, kumquat=7, fig=58, quince=199) e 33 blocos. Em cada bloco, uma constante nova recebe XOR com as 8 frutas e o resultado é mapeado para um caractere ASCII via um switch gigante.

Como ❌ é o operador XOR do Emojicode, todas as chaves se anulam:

K = 90 ^ 17 ^ 204 ^ 51 ^ 113 ^ 7 ^ 58 ^ 199   # = 0x3F
flag = ''.join(chr(c ^ K) for c in consts)

11. Técnica vs. malware real

O desafio é didático, mas usa as mesmas primitivas de um dropper/loader de malware:

Presente no CTFUso em malware real
Loader multi-estágioStagers, packers e shellcode loaders
XOR/rotates/AES + compressãoOfuscação e criptografia de payload
Blobs em constantes de stringEvasão de AV/EDR estático
Execução via interpretadoresLOLBins para burlar whitelisting
Branches e arquivos decoyAnti-sandbox / anti-análise

O que falta para ser malware “de verdade”: execução em memória (reflective loading/injection), C2, persistência, anti-VM/anti-debug e uma cadeia de toolchains viável. A defesa é a mesma usada aqui: emular os decoders, inspecionar entropia e strings, e monitorar interpretadores que gravam executáveis.

12. Conclusão

Um exercício excelente de leitura de código e reimplementação de decoders. A regra de ouro foi nunca executar o binário original: cada camada foi traduzida para Python (ou executada em ambiente isolado, no caso do Java) até sobrar apenas texto.
